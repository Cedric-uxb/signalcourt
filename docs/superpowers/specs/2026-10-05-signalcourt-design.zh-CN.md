# SignalCourt 设计文档

英文版本：[2026-10-05-signalcourt-design.md](2026-10-05-signalcourt-design.md)

## 产品概述

SignalCourt 是一个以证据为核心的加密新闻审查 Agent。它服务于这样一类用户：看到可能影响市场的新闻标题后，希望判断这条新闻是否足以支持一笔模拟交易。

系统会核验文章的核心声明，将新闻与 RYO 的实时市场证据联系起来，让受约束的看多 Agent 和看空 Agent 进行辩论，最后把决策保存为可以复盘的凭证。

本产品仅用于教育和研究。它不会执行交易、访问钱包，也不会把输出包装成投资建议。

## 参赛目标

主要目标是 RYO-CHAN 的 Autonomous Agents 赛道。同一个 BUIDL 也将参加 Dashboards & Interfaces 赛道，因为证据分析工作台是产品的重要组成部分。实现时必须保证两个赛道都能被单独理解和评分。

SignalCourt 对应以下官方评分重点：

- 把独立新闻证据与多个 RYO 研究工具组合成决策，而不是只展示单次 API 返回。
- 清楚展示从证据到结论的因果路径。
- 保存可重复验证的推理过程和数据来源。
- 当外部服务中断、失败或限流时，仍然诚实地运行。
- 让评委在 30 秒内理解最重要的结果。

## 目标用户与核心决策

第一版面向非专业的加密市场研究者。他们看到关于某个代币的热门新闻，但无法判断这条新闻是否真实、是否已经反映在市场价格中。

产品要帮助用户回答的不是“市场一定会怎么走”，而是：

> 这条新闻是否已经得到足够验证，并且当前市场证据是否足以支持一笔模拟仓位？

用户输入：

- 一个公开新闻网址。
- 一个代币符号。
- 风险级别：保守、平衡或激进。

系统只会返回三种模拟决策之一：`LONG`、`SHORT` 或 `NO_TRADE`。

## 核心用户流程

1. 用户提交新闻网址、代币符号和风险级别。
2. 系统读取文章并提取少量可以核验的核心声明。
3. Verifier Agent 搜索独立来源，寻找支持或反驳证据，并把每条声明标记为：已验证、有争议、缺乏支持或暂时不可用。
4. Research Coordinator 只调用与当前决策相关的 RYO 工具：`market_overview`、`analyze_token`、`deep_analysis` 和 `monitor_market_sentiment_shift`。
5. Bull Agent 和 Bear Agent 接收同一个不可修改的证据包。每个论点都必须引用证据编号。
6. Judge Agent 在考虑双方论点前，先执行确定性的证据门槛和风险检查。
7. 系统生成决策凭证，并在分析工作台中展示结果。
8. 用户复盘凭证时，系统使用已经保存的证据重新得出相同决策，不再次调用网络服务。

## 决策规则

只有同时满足以下条件，Judge Agent 才能返回 `LONG` 或 `SHORT`：

- 至少一条核心新闻声明得到独立来源支持。
- RYO 返回了可用的主要市场和技术指标证据。
- 看多和看空论点都包含有效的证据引用。
- 系统可以在不编造缺失数值的情况下计算模拟入场价、止损价、目标价和仓位大小。

任一条件失败时，结果必须是 `NO_TRADE`。稳定的原因代码会说明失败原因，例如：

- `CLAIM_UNSUPPORTED`：新闻声明没有得到支持。
- `MARKET_DATA_UNAVAILABLE`：市场数据不可用。
- `CITATION_INVALID`：Agent 引用的证据不存在或无效。
- `RISK_INPUT_INCOMPLETE`：风险计算所需信息不完整。

LLM 可以提取声明，并撰写受证据约束的看多、看空论点。确定性代码负责验证引用、执行决策门槛、计算风险参数和生成最终凭证。LLM 不能绕过失败的门槛。

## 系统架构

SignalCourt 使用 TypeScript 单仓库结构，分为三个职责清晰的区域。

### Web 客户端

使用 React 和 Vite 构建分析工作台，并把分析请求提交给服务器。浏览器端永远不会接触 RYO builder key 或其他私密凭证。

### 应用服务器

Node.js 服务负责：

- 验证输入。
- 读取公开新闻页面。
- 调用 Tavily Search 和 RYO REST 工具。
- 协调 Agent 提示词。
- 验证模型输出。
- 提供决策凭证和复盘接口。

Agent 通过一个服务端 OpenAI-compatible 模型接口运行。接口由 `LLM_BASE_URL`、`LLM_API_KEY` 和 `LLM_MODEL` 配置。系统没有隐藏的备用模型；如果缺少凭证或模型调用失败，只能返回明确的“不可用”状态。

RYO 适配器会在服务启动时读取实时工具目录，使用结构化的 `data` 字段进行决策，并在证据包中保留 `status`、`data_mode`、`as_of`、`availability` 和 `warnings`。

### 决策凭证存储

本地演示使用 SQLite 保存不可修改的证据包和决策凭证。凭证通过内容哈希引用证据。每次新分析都会创建新记录，不会原地修改旧凭证。

## 数据结构

每条证据包含：

- 稳定的证据编号和内容哈希。
- 来源类型，以及来源网址或 RYO 工具名称。
- 获取时间。
- 结构化数据。
- 可用性和来源状态。
- 供人阅读的摘要；摘要不能单独作为决策依据。

每份决策凭证包含：

- 凭证编号和结构版本。
- 用户输入和风险级别。
- 证据哈希与时间戳。
- 新闻声明核验结果。
- 带证据引用的看多和看空论点。
- 决策门槛结果和原因代码。
- 模拟决策、置信度，以及可用时的入场、止损、目标和仓位大小。
- 模型名称和提示词版本。
- 复盘验证结果。

## 界面设计

主页面是一个以工作效率为目标的分析工作台，不做成营销落地页。页面包含四个稳定区域：

- 输入栏：新闻网址、代币和风险级别。
- 声明账本：显示声明核验状态和来源。
- 证据与辩论时间线：展示从证据到结论的因果关系。
- 决策凭证：展示最终结论、失败门槛、风险参数和复盘状态。

视觉顺序按重要程度安排：先显示最终决策和失败门槛，再显示声明状态、因果推理和原始证据。桌面端使用紧凑的多栏布局；移动端使用 Decision、Claims、Debate 和 Evidence 四个标签页。

所有核心操作都支持键盘，状态不能只依赖颜色表达。

## 故障处理

- 网络错误、`429` 和 `503` 使用有次数上限的指数退避与随机抖动重试。
- 在适合的情况下，按照工具名称和标准化参数缓存新鲜的 RYO 结果。
- 可选来源失败时，保留一条“不可用”证据，不能用伪造数值替代。
- 核心证据缺失时返回 `NO_TRADE`，不能猜测结论。
- 所有外部服务离线时，已经保存的凭证仍然可以查看和复盘。
- 用户错误信息会说明失败阶段，但不会暴露凭证或服务器内部细节。

## 安全与负责任使用

- `RYO_MCP_KEY`、`TAVILY_API_KEY` 和模型凭证只保存在服务器端。
- `.env.example` 记录所需环境变量，`.env` 必须被 Git 忽略。
- 服务器只接受 HTTP 和 HTTPS 网址，并在抓取前阻止私有网络和本地网络地址，避免 SSRF。
- 新闻文章和外部证据全部视为不可信数据，不能被当作 Agent 指令执行。
- 代币符号和风险设置必须经过结构化验证。
- 界面明确标注所有仓位均为模拟决策，并声明 SignalCourt 不是投资建议。

## 测试策略

- 单元测试覆盖输入验证、声明状态、证据哈希、引用验证、风险计算、决策门槛和凭证生成。
- 集成测试使用录制的 RYO 与新闻数据，验证完整分析流程，不消耗实时额度。
- 故障测试覆盖限流、数据不可用、模型输出格式错误、文章中的提示词注入，以及离线复盘。
- 端到端测试覆盖提交文章、检查决策和复盘凭证，并验证桌面与移动布局。
- 单独提供一个可选的实时 smoke test，用于检查已认证的 RYO 工具目录和一次低成本工具调用；它不属于普通测试套件。

## 演示故事

两分钟演示从一条看起来可信、可能影响市场的热门新闻开始。

SignalCourt 提取核心声明，显示一个支持来源和一个反对来源，再把声明与当前 RYO 市场证据连接起来。观众可以看到看多和看空 Agent 引用同一个证据包进行辩论。Judge Agent 给出模拟决策后，演示者立即离线复盘该凭证，证明结果可以重复。

第二个简短案例会故意移除一项关键来源，展示系统返回 `NO_TRADE / INSUFFICIENT_EVIDENCE`，而不是制造答案。

## 第一版不做的功能

- 真实交易、钱包、余额或交易签名。
- 自动发布社交媒体内容或公开提醒。
- 持续监控创作者或聊天频道。
- 用户账户、付费功能或多人协作。
- 通用投资组合管理器。

这些限制让项目只聚焦一个关键决策，也方便评委快速检查证据路径。

## 验收标准

满足以下条件时，第一版实现完成：

- 用户可以提交受支持的新闻网址、代币和风险级别。
- 系统能把独立新闻证据与至少两个相关 RYO 工具组合起来。
- 每条辩论论点和最终理由都引用已保存的证据。
- 证据不足或不可用时，系统能确定性地返回 `NO_TRADE`。
- 已保存的凭证可以离线复盘，并得到相同的决策和原因代码。
- 核心流程支持键盘操作，并能在桌面和移动视口正常使用。
- 自动化测试覆盖决策门槛和关键浏览器流程。
- 仓库不包含真实密钥，并提供 `.env.example`。
